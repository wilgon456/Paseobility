# 참고 사례 조회 — docs MCP 사용법과 경로 판정

"다른 미니앱을 참고해 PRD를 깎는다"는 요구에 대해, **지금 에이전트가 실제로 닿을
수 있는 참고 자료는 공식 문서의 가이드·샘플**이다. 이 파일은 그 조회 절차와,
"공개 미니앱 목록 조회" 경로가 없다는 판정 근거를 함께 둔다.

## 경로 판정 (실측 2026-08-10)

| 후보 경로 | 판정 | 근거 |
|---|---|---|
| docs MCP(`apps-in-toss-docs`) | **있음** — 가이드·샘플·검수 기준 조회 | `tools/list` 실측: `searchDocumentation`·`getPage`·`askQuestion`·`sendFeedback` 4종 |
| docs MCP의 "미니앱 목록" tool | **없음** | 위 4종이 전부. 카탈로그 성격 tool 없음 |
| 콘솔 MCP(`ait-console`)의 공개 앱 조회 | **없음** | 콘솔 MCP의 전 도구(workspace·miniapp·bundle·review·push·iap·iaa·promotion·dashboard·event·notice·toss_login·image_upload_url)가 **자기 워크스페이스 scope**다 |
| 웹 미니앱 포털(공개 사례 브라우징) | **harness 산출물 아님** | 제품 결정 항목 — 이 skill에서 만들지 않는다 |

따라서 참고 사례 조회는 **docs MCP 단독**으로 한다. plan은 콘솔 MCP를 호출하지
않는다(분석 전용). 사용자가 "다른 팀 미니앱 목록을 보여달라"고 하면 그런 경로가
없다는 것을 그대로 말하고, 문서의 샘플·가이드로 대체한다 — 존재하지 않는 tool을
부르거나 목록을 지어내지 않는다.

## tool 4종 사용 구분

| tool | 언제 |
|---|---|
| `searchDocumentation({query})` | 키워드로 관련 페이지를 찾는다. 결과는 제목 + 링크 + 발췌 |
| `getPage({url})` | 위 결과의 링크를 **그대로** 넣어 전문을 읽는다. URL을 조합·추측하지 않는다 |
| `askQuestion({question, goal})` | 여러 페이지에 걸친 답이 필요할 때(예: "이 기능이 미니앱에서 가능한가"). `goal`에 PRD 목적을 넣으면 답이 그 목적에 맞춰진다 |
| `sendFeedback` | 문서 오류를 발견했을 때만. plan 흐름에서 기본으로 쓰지 않는다 |

## 단계별 질의어

아이데이션·PRD 단계에서 실제로 쓸 만한 질의어를 목적별로 묶었다. 결과가 비면
질의어를 바꿔 한 번 더 시도하고, 그래도 없으면 `(확인 필요)`로 남긴다.

**실현성 확인 (아이데이션 2단계)**

- `"샘플 코드"` / `"예제 모음"` — SDK가 실제로 무엇을 제공하는지
- `"시작하기"` — 연동 방식(클라이언트 SDK / 서버 API)의 경계
- `"iframe"` — 외부 페이지 임베드 제약
- 도메인 이름 그대로(`"인앱결제"`, `"토스 로그인"`, `"위치"` 등) — 그 기능이
  문서에 존재하는지, 제약이 무엇인지

**검수 리스크 확인 (PRD 8번 섹션)**

- `"출시 전 체크리스트"` / `"미니앱 출시하기"` — 출시 전 확인 항목
- `"검수 가이드라인"` — 검수가 보는 축(서비스·기능·디자인·보안)
- `"미니앱 카테고리"` — 카테고리 선택과 실제 서비스 일치 요구
- `"프로모션"` — 프로모션·사행성 관련 충족 조건

**화면·UX 확인 (PRD 4번 섹션)**

- `"뒤로가기"` / `"화면 전환"` — 네비게이션·swipe-back 거동
- `"권한"` — 권한 요청 패턴과 거부 시 처리

## 결과를 PRD에 반영하는 방식

- 문서에서 확인한 제약은 PRD 8번(검수 리스크)에 **문장 그대로의 요지**로 옮긴다.
  원문 링크는 PRD에 붙이지 않는다 — 필요할 때 같은 질의어로 다시 찾는다.
- 문서가 답하지 못한 항목은 `(확인 필요)`로 남기고 계획 블록의 "확인이 필요한
  항목"에도 함께 올린다.
- 문서 발췌를 근거로 SDK 메서드 이름·권한 상수를 확정할 때는 그 페이지를
  `getPage`로 열어 확인한 뒤에만 쓴다. 검색 발췌만 보고 단정하지 않는다.
