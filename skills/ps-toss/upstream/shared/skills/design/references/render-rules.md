# 렌더 규칙 (render rules)

design skill이 화면을 실제로 그릴 때 따르는 규칙의 정본이다. 규칙은 3층으로
나뉘고, 층마다 지위가 다르다.

## 이 파일의 지위

| 층 | 지위 | design의 처리 |
|---|---|---|
| 1층 — 하드 | 차단, 예외 없음 | 위반을 발견하면 design이 직접 고친다. 고쳐지지 않으면 완료가 아니다 |
| 2층 — 권장 | 소프트 | 위반은 목록으로 남기고 진행한다. 자동으로 고치지 않는다 |
| 3층 — 자유 | 제작자의 몫 | design은 판정하지 않는다. 완성도를 높이는 방향으로만 돕는다 |

## 대전제 — 자유도가 먼저다

앱인토스에 올라오는 앱은 제3자 앱이다. **토스처럼 만들지 않는다.** 브랜드색·
폰트·레이아웃은 제작자의 것이고, 이 파일의 목적은 "토스답게 통일"이 아니라
"못생기거나 위험하지만 않게 하는 바닥"을 까는 것이다.

| 층 | 성격 | 어긴다는 것은 |
|---|---|---|
| 1층 플랫폼 제약 | 하드, 예외 없음 | 앱이 앱인토스에서 깨지거나 유저를 해침 |
| 2층 품질 권장 | 소프트, "잘 만들자" | 그냥 못생김 |
| 3층 자유 | 제작자의 몫 | 어기는 게 아니라 개성임 |

## 과잉 지적 금지 — 이건 문제가 아니다

바닥만 잡고, 아래는 문제 삼지 않는다. 제작자의 자유이거나 취향이다.

- **광고가 있는 것 자체.** 상단·하단에 광고가 있어도 구분이 명확하고 콘텐츠를
  가리지 않으면 괜찮다(문제는 아래 1-6에 해당할 때만).
- **버튼이 여러 개 나열된 것.** 버튼 개수 자체는 문제가 아니다.
- **각진 버튼·카드.** 못생김의 영역이지 하드 위반이 아니다. 둥글게는 2층 권장.
- **말장난·유머 카피.** 톤은 제작자 것이다(카피는 `/ait:ux-writing`).
- **보상형 광고.** "광고 보고 ○○ 받기"처럼 유저에게 실익을 주는 광고는 좋은
  패턴이다.

## 플랫폼 — 웹 단일

앱인토스 미니앱 화면은 웹(web-framework, React DOM)으로 렌더한다. 아래 모든
규칙·수치·코드 스니펫은 웹 DOM/CSS 기준이다 — RN 네이티브 컴포넌트를 전제하지
않는다.

## 기본 토큰 — 역할과 위계

이 기본값은 TDS 호환·인증을 뜻하지 않는 중립 기본값이며, 프로젝트가 자체 값을
정하면 그쪽이 우선한다(Figma에서 읽어 온 토큰 포함). **값의 정본은
`../assets/project/tokens.css` 하나다** — 화면을 그리기 전에 그 파일을 Read
한다. 여기서는 역할과 위계만 설명한다.

- **텍스트 그레이스케일 6단계** — 강조·기본·보조·힌트·비활성·반전. 검정(`#000`)
  은 쓰지 않는다. 예외는 dim overlay(`--dim`, `rgba(0, 0, 0, 0.4)`) 하나뿐이다
  — 다이얼로그·바텀시트 뒤 오버레이처럼 텍스트·배경색이 아닌 용도에만 쓰므로
  대비 문제를 만들지 않는다.
- **배경 2종** — 기본 배경, 회색 캔버스 배경.
- **상태색 3종** — 위험·성공·경고. 근거는 H(harness 기준)다 — 공식 규격으로
  단정하지 않는다.
- **타이포 스케일 6단계** — Display·Title·Subtitle·Body·Body-small·Caption.
  크기는 이 스케일 안에서만 고른다. `font-weight`는 400~700 범위에서만 쓴다 —
  800·900(extra bold)을 남발하지 않는다. 가늘어도 400 아래로 내려가지 않고,
  선택한 폰트가 실제로 가진 굵기만 쓴다(폰트에 없는 굵기를 브라우저가 흉내 내면
  글자가 뭉개진다).
- **간격 스케일 6단계** — `--space-1`~`--space-6`(4/8/12/16/24/32px).
- **브랜드 강조색** — `--brand-primary`. 3층에서 자유롭게 바꾼다.

## 1층 — 하드 (예외 없음)

강제 항목: **① 글자 최소 크기 ③ 한글 word-break ④ 대비·어포던스 ⑤ 터치·
safe area ⑥ 광고 배치 ⑦ 레이아웃 무결성 ⑧ 다크패턴 금지 ⑨ 꺾쇠·화살표 ⑩ 상단
네비 미포함.** 렌더 후 완료 기준으로 전부 확인한다. ② 이모지 Tossface는 번호만
이 자리에 두고 등급은 권장이다(아래 1-2).

### 1-1 글자 크기 — 최우선 강제

가장 흔한 저품질 신호가 "글자를 너무 작게 욱여넣는 것"이다. 이 규칙을 다른
무엇보다 먼저 지킨다.

- **11px 이하 절대 금지.** 화면의 어떤 텍스트도 11px 이하로 두지 않는다.
  렌더를 다 한 뒤 **전체 텍스트를 전수 스캔해 11px 이하가 하나도 없는지
  확인한다**(권장 하한은 13px).
- **본문(읽는 텍스트)은 최소 15px, 권장 17px.** 리스트 항목·설명·값 등 유저가
  실제로 읽는 텍스트를 15px 아래로 두지 않는다.
- **메인 액션·타이틀은 위계상 충분히 크게.** 그 화면의 핵심 행동을 칩·캡션처럼
  작게 쓰지 않는다. 화면에서 가장 눈에 띄어야 한다.
- **핵심 정보를 caption(13px) 크기에 담지 않는다.** 13px는 메타데이터·보조
  라벨 전용이다.
- **문장 안에서 글자 크기를 튀게 바꾸지 않는다.** 숫자 하나만 확 키우는 식으로
  한 문장·구 안에서 크기를 들쭉날쭉 변형하지 않는다.
- **큰 건 문제가 아니다.** 히어로 숫자·타이틀은 32px 안팎이 기본이고 더 키워도
  된다. 강제는 하한이다.

크기·색·weight는 위 "기본 토큰"의 타이포 스케일과 텍스트 그레이스케일을 쓴다.

### 1-2 이모지 — Tossface 권장 (차단 아님)

> 모든 모드에서 권장이다. 공식 문서에 근거가 없는 하네스 자체 기준이라 완료를
> 막지 않고 자동 수정 대상도 아니다. 토스 앱 webview에서 CDN 로드는
> 확인됐다(2026-10-14, iOS 실기기·Android 에뮬레이터). 기성 디자인 시스템 프로젝트에는 전역 서체를 주입하지
> 않는다(아래 "존중 모드" 절).

**권장 형상: 모든 이모지가 Tossface로 렌더된다** — 진입 CSS 폰트 스택 맨 앞에 배선되거나
(`base.css`가 이미 이렇게 배선한다), 개별 요소에 `.tf`가 붙어 있다.
`--no-tossface`로 스캐폴딩된 프로젝트는 이 항목이 해당 없음이다.

아이콘뿐 아니라 본문·데이터·유저 입력 문자열 안에 섞인 이모지(예: `✅ 완료`,
`⚠️ 주의`)도 전부 포함한다.

```css
@import url('https://cdn.jsdelivr.net/gh/toss/tossface/dist/tossface.css');
.tf { font-family: 'Tossface'; font-style: normal; }
```

모든 이모지를 `<span class="tf">…</span>`로 감싼다. 텍스트를 렌더할 때 아래
정규식으로 전부 잡는다(VS16·ZWJ 조합까지 커버):

```js
const EMOJI_RE = /(\p{Extended_Pictographic}(?:️|‍\p{Extended_Pictographic})*)/gu;
const wrapEmoji = s => esc(s).replace(EMOJI_RE, '<span class="tf">$1</span>');
```

유저 콘텐츠를 표·카드에 뿌릴 때 `esc()`만 하고 끝내지 않는다. 반드시
`wrapEmoji`를 거친다. 정적 HTML이면 이모지가 들어가는 span에 `class="tf"`를
직접 붙인다.

### 1-3 한글 줄바꿈 — 강제

> 존중 모드에서 권장으로 강등 — 프로젝트의 전역 CSS를 건드리지 않는다.

한국어 텍스트가 **어절 중간에서 끊기지 않게** 한다. `word-break: keep-all` +
긴 URL·영문 토큰 대비 `overflow-wrap: break-word`를 건다(`base.css`의 `body`가
이미 기본으로 걸어 둔다). 이모지 Tossface와 함께 지키는 전역 텍스트 규칙이다.

### 1-4 대비·어포던스

- **대비를 지킨다.** 배경 위 텍스트가 읽히게 한다. 너무 흐린 회색 텍스트·
  버튼처럼 배경에 파묻혀 안 읽히는 조합을 쓰지 않는다.
- **버튼은 버튼처럼 보이게 한다.** 배경과 구분되는 배경색·테두리·그림자 중
  최소 하나를 갖는다 — 눌러야 하는 요소가 배경과 구분 안 돼 버튼인지 모르는
  상태를 만들지 않는다.

### 1-5 터치·safe area

- **터치 타겟 최소 44px.** 누르는 요소는 시각 크기가 작아도 탭 영역을 44px로
  확보한다.
- **하단 CTA는 safe area 여백을 둔다.** 화면 하단에 고정되는 CTA·바는 34px
  안전 여백을 둬서 화면 맨 밑에 딱 붙지 않게 한다.

### 1-6 광고 배치

광고가 있는 것 자체는 문제가 아니다. 아래일 때만 문제다.

- **광고가 콘텐츠를 가리지 않는다.** 화면 절반을 덮는 광고, 콘텐츠 위에 얹힌
  광고는 금지.
- **첫 화면 콘텐츠(ATF)를 밀어내지 않는다.** 광고 때문에 첫 화면에서 핵심
  콘텐츠·액션이 접힘 아래로 밀려나지 않게 한다.
- **콘텐츠와 광고를 명확히 구분한다.** AD 배지 등으로 광고임을 알 수 있게.
  콘텐츠인지 광고인지 헷갈리게 두지 않는다.
- **하단 탭바가 있으면 광고 배너를 화면 바닥에 고정하지 않는다.** 탭바가 있을
  땐 광고를 콘텐츠 중간에 넣는다(바닥 고정 광고는 탭바가 없을 때만).
- **광고의 클릭 영역이 콘텐츠 클릭 영역을 침해하지 않는다.**

### 1-7 레이아웃 무결성

실제 코드 결함으로 생기는 깨짐을 남기지 않는다.

- **텍스트가 다른 요소와 겹치지 않는다.** 특히 요소를 음수 마진(`margin-top:
  -N` 등)으로 끌어올려 겹치게 만들지 않는다 — 위 형제 텍스트가 2줄이 되는
  순간 바로 겹친다.
- **요소가 화면 밖으로 잘리지 않는다.** 카드·이미지가 우측·하단으로 잘려나가지
  않게 한다.
- **의도 없는 여백·정렬 어긋남을 남기지 않는다.** 우측에 빈 여백이 생기거나,
  특정 요소만 이유 없이 들여쓰기되지 않게 한다.
- **이미지 비율을 유지한다.** 원본 비율을 무시해 찌그러진 이미지를 두지
  않는다.
- **과대한 이미지가 핵심 액션을 밀어내지 않는다.** 이미지 영역이 불필요하게
  커서 하단의 핵심 액션이 안 보이면 이미지 높이를 줄인다.
- **바텀시트엔 닫기 어포던스를 둔다.** 닫기 버튼 없이 길게 밀어야만 닫히는
  상태를 만들지 않는다.
- **화면 배경색은 디바이스(뷰포트) 전체를 채운다.** `.canvas`(`base.css`)로
  `min-height: 100vh`/`100dvh`를 걸어, 배경을 콘텐츠 높이만큼만 깔아서
  아래쪽이 빈 흰 여백으로 남지 않게 한다.

### 1-8 다크패턴 금지

- **예상치 못한 전면광고 금지.** 탭·스크롤 같은 일반 동작 중에 맥락 없는
  전면 광고·다이얼로그를 끼워 넣지 않는다.
- **진입 첫 순간을 전면 요소로 막지 않는다.** 화면을 열자마자 광고·동의
  바텀시트·다이얼로그로 콘텐츠를 가로막지 않는다. 가치를 먼저 보여준다.
- **이탈을 가로막지 않는다.** 뒤로·닫기를 눌렀는데 안 나가지고 붙잡는 시트를
  띄우지 않는다(입력하던 내용이 사라진다는 안내 다이얼로그 정도는 예외).
- **탈출로 없는 화면(dead end)을 만들지 않는다.** 제작자가 원하는 CTA 말고도
  뒤로·닫기처럼 나가는 길이 늘 있어야 한다.
- **가짜 버튼·닫기 숨김·강제 행동 유도 금지.**
- **같은 동작을 하는 CTA를 한 화면에 중복해서 두지 않는다.**
- **광고를 콘텐츠인 척 위장하지 않는다.** 광고는 숨기는 대상이 아니라 3층에서
  "유저가 반기는 광고"로 만든다.

### 1-9 꺾쇠·화살표 — UI 품질을 가장 크게 가르는 요소

> 존중 모드에서 권장으로 강등 — 아이콘 세트를 바꾸지 않고 프로젝트의 아이콘
> 체계를 쓴다(아래 "존중 모드" 절).

방향 화살표·꺾쇠(chevron)를 잘못 쓰는 게 UI 품질을 가장 크게 떨어뜨린다.
여기는 특히 엄격하게 지킨다.

- **버튼 안에는 방향 화살표·꺾쇠를 넣지 않는다.** 버튼은 액션이지 이동 표시가
  아니다(화살표는 링크·리스트 행의 이동 어포던스에만 쓴다).
- **이동·진입을 나타내는 꺾쇠는 텍스트 문자로 그리지 않는다.** `>` `‹` `›` `»`
  `^` `v` 같은 문자로 꺾쇠를 만들지 말고 **반드시 SVG 아이콘**을 쓴다.
- **아이콘은 제작자 자신의 세트나 오픈 라이선스 아이콘, 또는 앱인토스가
  제공하는 아이콘 라이브러리를 쓴다.** 토스 내부 아이콘은 외부 제작자용으로
  라이선스가 열려 있지 않을 수 있으니, 확인 없이 링크·번들하지 않는다. 세트가
  없으면 `../assets/project/icons/` 6종을 쓴다(아래 부록).
- 색을 바꿔야 하면 svg에 `stroke="currentColor"`(또는 `fill="currentColor"`)로
  부모 색을 상속시킨다.

아래 용도엔 텍스트 글리프(`>` `<` `^` `v` `×` `⌕` `♡` `★` `⋯`)가 아니라 SVG
아이콘을 쓴다.

| 용도 | 모양 |
|---|---|
| 리스트 행 진입 | 오른쪽 꺾쇠 |
| 뒤로가기 | 왼쪽 화살표 |
| 펼침·접힘 | 아래·위 화살표 |
| 검색 | 돋보기 |
| 닫기 | X |
| 더보기·찜·별점 등 | 각 의미의 SVG 아이콘 |

### 1-10 상단 네비게이션 — 그리지 않는다 (앱인토스가 자동으로 붙임)

앱인토스는 미니앱 화면 상단에 네비게이션 바(뒤로가기·화면 제목·닫기)를
**플랫폼이 자동으로 붙인다.** 화면 디자인 안에 상단 네비바를 직접 그리지
않는다 — 그리면 네비바가 두 겹으로 겹친다.

- 콘텐츠는 상단 네비 아래부터, **본문 첫 요소부터** 시작한다. 뒤로가기(‹)
  화살표를 콘텐츠 맨 위에 넣지 않는다.
- 화면 제목·우측 액션(저장·설정 등)이 필요하면 콘텐츠에 그리지 말고
  **플랫폼 네비(타이틀·right 버튼)**로 넣는다.
- 예외: 네비 위에 겹치는 **투명·커스텀 히어로**가 정말 필요한 특수 화면
  정도. 기본은 "상단 네비 없음".

## 존중 모드 — 기성 디자인 시스템이 있는 프로젝트

`SKILL.md` 1단계가 기성 디자인(TDS·MUI·Tailwind·shadcn·자체 토큰 등)을 감지하면
모드 A·B 위에 존중 모드가 얹힌다. 생김새는 프로젝트가 이미 정했으므로 이 문서의
기본 토큰 값은 쓰지 않고, 컴포넌트와 값은 프로젝트의 것으로만 그린다.

- **강제하는 항목**: 1-1, 1-4, 1-5, 1-6, 1-7, 1-8, 1-10. 플랫폼·안전 항목이라
  프로젝트의 디자인 시스템 안에서도 같은 기준이다. 고칠 때도 프로젝트의 값과
  유틸리티(Tailwind 클래스, DS 컴포넌트 prop 등)로 고친다.
- **권장으로 내리는 항목**: 1-3, 1-9(1-2는 모든 모드에서 이미 권장이다). 전역 폰트 CDN·전역 CSS·아이콘 세트를
  주입하지 않는다. 목록으로도 먼저 내밀지 않고, 사용자가 물을 때만 말한다.
- 기본 토큰 값, 정적 자산(`tokens.css`·`base.css`·아이콘), entry 배선은 건너뛴다.

## 2층 — 권장 (소프트, "잘 만들자")

- **위계.** 크기·굵기·색으로 정보의 우선순위를 만든다. 모든 텍스트를 같은
  크기로 나열하지 않는다.
- **크기는 정해진 스케일로만.** 글자 크기를 제각각 쓰지 않는다.
- **강조색은 절제.** 한 화면에서 강조 컬러를 여러 개 남발하지 않는다.
- **정렬.** 좌측 기준선을 통일한다. 특정 요소만 이유 없이 들여쓰기하지 않는다.
- **간격.** 같은 그룹은 좁게, 다른 그룹은 넓게. 일관된 간격 스케일(위 `--space-*`)
  을 쓴다.
- **같은 그룹의 컨트롤 크기를 맞춘다.** 나란히 놓인 입력 필드·버튼의 높이를
  통일한다.
- **둥근 버튼·카드 권장.** 각진 사각 버튼·카드보다 radius를 준 형태가 낫다.
- **주요 CTA는 하단 고정 권장.** 화면의 대표 행동이 있으면 하단에 고정하는
  편이 낫다.
- **적절한 입력 컨트롤을 쓴다.** 긴 선택지는 피커·스피너로. 옵션을 리스트로
  전부 펼쳐 스크롤을 늘리지 않는다.
- **한 화면 정보량을 절제한다.** 칩·텍스트를 과하게 밀어 넣지 않는다.
- **손톱 금지.** radius가 있는 박스에 **한쪽 면에만** 선·색띠를 넣지 않는다 —
  모서리에서 직각으로 잘려 손톱처럼 지저분해진다. 구현 수단 불문 전부 금지:
  `border-left/top/right/bottom` 단독, `box-shadow: inset` 한쪽,
  `::before/::after` 세로 색띠, `linear-gradient` 색띠. **둥근 카드에 3~7px
  단색 accent border를 두르는 것**도 대표적 AI slop이다. 강조가 필요하면
  **4면 균일 테두리(옅게)·배경 틴트·내부 배지/번호**로 한다(예외: radius가
  **없는** 요소의 한쪽 divider — 리스트 구분선, blockquote 왼쪽 룰 — 는
  손톱이 아니라 허용).
- **그림자(shadow) 절제.** 버튼·카드·입력·리스트 행에 drop shadow를 남발하지
  않는다 — 그럴듯해 보이려 그림자를 두르는 건 대표적 AI slop이다. 그림자는
  tooltip·다이얼로그·바텀시트처럼 실제로 떠 있는 요소에만 옅게 쓴다.
- **카드·행의 좌우 여백은 대칭으로.** 우측에 아이콘·꺾쇠가 붙어 한쪽만 넓어
  보이는 불균형을 만들지 않는다.
- **TDS-like 컴포넌트는 선택.** 빠르게 만들고 싶으면 토스식 리스트·버튼·시트
  패턴을 참고해도 된다. 강제가 아니며, TDS를 직접 연결하지 않는다.

정보 구성 휴리스틱:

- **인접한 블록엔 최소 간격을 둔다.** `gap: 0`으로 두 블록이 붙으면 하나로
  읽혀 정보 계층이 사라진다.
- **배경·틴트가 있는 박스엔 radius와 사방 padding.** 좌우 padding을 0으로
  두면 텍스트가 가장자리에 붙는다.
- **단일 목적 화면엔 글로벌 탭바를 넣지 않는다.** 완료·결과·인증·모달·빈 상태
  화면엔 탭바를 빼고, 탭바는 메인 탭 화면에만 둔다.
- **빈 화면을 만들지 않는다.** 첫 화면·히어로엔 최소 한 줄 텍스트와 아이콘·
  그래픽을 둔다. 빈 상태에는 다음 액션을 함께 넣는다.

## 3층 — 자유 (제작자의 몫)

이 층은 규칙이 아니라 제작자의 개성이다. design의 역할은 통일시키는 게
아니라 완성도를 높이는 것이다.

- **브랜드색 자유.** 토스 파랑을 강제하지 않는다. 제작자의 색을 쓰되 1층의
  대비, 2층의 강조색 절제만 지킨다.
- **본문 폰트 자유.** 제작자가 자기 폰트를 쓸 수 있다(1층의 최소 크기만
  준수). Tossface는 **이모지에만** 권장한다.
- **일러스트·톤·레이아웃 자유.** 앱 개성대로. 다른 서비스의 결을 참고해도
  된다.
- **광고는 억제·위장 대상이 아니다.** 광고 가치화 5축으로 "유저가 반기는
  광고"를 설계한다.

| 축 | 질문 |
|---|---|
| 관련성 | 이 유저·이 순간에 진짜 맞는 제안인가 |
| 보상 | 유저가 얻는 이득이 먼저 보이는가 |
| 자기표현 | 공유·참여가 유저를 돋보이게 하는가 |
| 재미 | 행위 자체가 즐거운가 |
| 정직함 | 광고임을 숨기지 않고 당당히 가치를 제시하는가 |

Product Ethics가 상위다. 관련성 없는 강매, 기만, 사행성 과장은 광고 가치화가
아니라 착취다. 정직함 축이 무너지면 안 된다(같은 렌즈가 `build-mode.md`에도
있어 감지 단계와 이어진다).

## 부록: CSS entry 배선 절차

이 절차는 `scripts/inject-project-guide.sh`가 실행한다 — 기록용 정본이고,
화면을 그리는 쪽이 손으로 따라 하지 않는다. 화면 코드에서 `base.css`·`tokens.css`를
다시 import하지 않는다. 스크립트는 이미 배선돼 있으면 다시 넣지 않는다
(idempotent).

1. **탐지 순서** — 아래 순서로 첫 번째로 존재하는 파일을 진입점으로 본다:
   `src/main.tsx` → `src/main.ts` → `src/index.tsx` → `src/index.ts` →
   `index.tsx` → `index.ts`.
2. **idempotency 확인** — 그 파일과 `index.html` 양쪽에서 `styles/base.css`를
   grep한다. 어느 한쪽에라도 잡히면 skip(`index.html`의 `<link>`로 이미 걸려
   있는데 진입점에 import를 더하면 두 번 로드된다).
3. **vite/client 가드** — `src/vite-env.d.ts` 존재 또는 tsconfig `types`에
   `vite/client` 포함 여부를 확인한다. 있으면 진입점 첫 import 줄에
   `import './styles/base.css';`를 추가한다.
4. **`index.html` 폴백** — 진입점 후보가 전부 없거나 `vite/client` 앰비언트
   타입이 없으면 JS import를 포기하고 `index.html`의 `</head>` 앞에
   `<link rel="stylesheet" href="/src/styles/base.css" />`를 추가한다.

grep으로 이미 배선을 확인했는데도 또 추가하면 `@import`가 두 번 실행돼
낭비다 — 매 실행 전에 반드시 2번을 먼저 거친다.
