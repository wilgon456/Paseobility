# 디자인 근거 조회 — docs MCP 사용법

design이 "앱인토스에서는 이렇게 하는 게 맞다"고 말하려면 근거가 있어야 한다.
에이전트가 실제로 닿을 수 있는 근거는 **공식 문서**뿐이고, 조회 경로는 docs
MCP(`apps-in-toss-docs`) 하나다. 이 파일은 그 조회 절차와, 디자인 단계에서 실제로
쓸 질의어를 둔다.

## 조회 경로 (실측 2026-08-10)

| 후보 경로 | 판정 | 근거 |
|---|---|---|
| docs MCP(`apps-in-toss-docs`) | **있음** | `tools/list` 실측: `searchDocumentation`·`getPage`·`askQuestion`·`sendFeedback` 4종 |
| docs MCP의 "디자인 리소스 다운로드" tool | **없음** | 위 4종이 전부. 파일 배포 성격 tool 없음 |
| 콘솔 MCP(`ait-console`)의 디자인 가이드 조회 | **없음** | 콘솔 tool은 자기 워크스페이스 scope의 등록·번들·검수 축이다 |
| 토스 디자인 시스템(TDS) 조회 | **하지 않는다** | SKILL.md의 TDS 방침 — 모사·의존을 권하지 않는다 |

**docs MCP는 위 4종만 쓴다.** 다른 tool 이름을 지어내지 않고, 검색 결과가 없으면
없다고 말한다.

## tool 4종 사용 구분

| tool | 언제 |
|---|---|
| `searchDocumentation({query})` | 키워드로 관련 페이지를 찾는다. 결과는 제목 + 링크 + 발췌 |
| `getPage({url})` | 위 결과의 링크를 **그대로** 넣어 전문을 읽는다. URL을 조합·추측하지 않는다 |
| `askQuestion({question, goal})` | 여러 페이지에 걸친 답이 필요할 때. `goal`에 "미니앱 화면 설계" 같은 목적을 넣으면 답이 그 목적에 맞춰진다 |
| `sendFeedback` | 문서 오류를 발견했을 때만. design 흐름에서 기본으로 쓰지 않는다 |

## 단계별 질의어

질의어는 **후보**다 — 결과가 비는 것은 정상이고, 그때는 질의어를 한 번 바꿔
재시도한 뒤 `(확인 필요)`로 남긴다. 없는 가이드를 지어내지 않는다.

**화면 구조·네비게이션 (SKILL.md 2-B단계 / quality bar G1)**

- `"뒤로가기"` / `"화면 전환"` — swipe-back·네비게이션 거동
- `"진입"` — 진입 경로·초기 화면 컨텍스트
- `"권한"` — 권한 요청 패턴과 거부 시 처리(quality bar G5-4)

**렌더·자동 수정 (SKILL.md 3·4단계 / quality bar G1-1·G1-3·G1-6)**

차단 등급을 코드로 고치기 전에, 수치·구조를 문서가 따로 정하고 있는지 본다.

- `"safe area"` — 상하단 inset 처리. 문서가 값을 정하고 있으면 1층의 통용
  하한(34px)보다 그쪽이 정본이다
- `"상단 네비게이션"` — 컨테이너가 자동으로 붙이는 네비 바의 범위와, 화면
  안에 직접 그리면 안 되는 영역

**등록 자산 (SKILL.md 5·6단계 / quality bar G2)**

- `"미니앱 등록"` / `"아이콘"` / `"스크린샷"` — 등록이 요구하는 자산과 규격
- `"미니앱 카테고리"` — 카테고리 선택과 실제 서비스 일치 요구

**검수 리스크 (quality bar G6-5)**

- `"검수 가이드라인"` — 검수가 보는 축(서비스·기능·디자인·보안)
- `"출시 전 체크리스트"` — 출시 전 확인 항목

**광고 (quality bar G8-5)**

- `"광고"` — 광고 게재 방식이 검수 안내와 맞는지

## 결과를 판정에 반영하는 방식

- 문서에서 확인한 항목만 quality bar의 **D 근거 항목을 "확인됨"으로 바꾼다**.
  검색 발췌만 보고 단정하지 말고, 근거로 삼을 페이지는 `getPage`로 열어 확인한다.
- 문서가 답하지 못한 항목은 `(문서 확인 필요)`로 남기고 완료 안내에 그대로
  노출한다.
- 문서 링크를 skill 산출물에 인쇄하지 않는다 — 필요할 때 같은 질의어로 다시
  찾는다(`docs.aitc.dev` 링크 금지 규약과 같은 이유).
- 문서에 있는 규격과 SKILL.md의 규격표가 어긋나면 **문서 쪽을 정본으로 보고**
  어긋난 지점을 사용자에게 알린다. 임의로 규격표 값을 바꿔 자산을 만들지 않는다.
