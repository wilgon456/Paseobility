# 디자인 가이드

이 프로젝트의 화면 디자인 규칙이다. `/ait:design`이 화면을 만들거나 고칠 때
따른다. 규칙은 3층이다 — 1층은 하드(`/ait:design`이 화면을 쓸 때 지킨다),
2층은 권장(목록으로만 남는다), 3층은 이 프로젝트의 개성이다.

앱인토스에 올라오는 앱은 제3자 앱이다. **토스처럼 만들지 않는다.** 브랜드색·
폰트·레이아웃은 제작자의 것이고, 이 가이드의 목적은 "토스답게 통일"이 아니라
"못생기거나 위험하지만 않게 하는 바닥"을 까는 것이다.

## 과잉 지적 금지

아래는 문제 삼지 않는다 — 제작자의 자유이거나 취향이다.

- 광고가 있는 것 자체(구분이 명확하고 콘텐츠를 가리지 않으면 괜찮다).
- 버튼이 여러 개 나열된 것.
- 각진 버튼·카드(둥글게는 2층 권장일 뿐 하드 위반이 아니다).
- 말장난·유머 카피(톤은 제작자 것이다).
- 보상형 광고("광고 보고 ○○ 받기"처럼 유저에게 실익을 주는 광고는 좋은
  패턴이다).

## 토큰

값의 정본은 `src/styles/tokens.css`다. 여기서는 역할만 적는다 — 실제 값이
필요하면 그 파일을 연다.

- 텍스트 그레이스케일 6단계(강조·기본·보조·힌트·비활성·반전). 검정(`#000`)은
  쓰지 않는다 — 예외는 dim overlay(`--dim`)뿐이다.
- 배경 2종(기본·캔버스).
- 상태색 3종(위험·성공·경고).
- 타이포 스케일 6단계(Display·Title·Subtitle·Body·Body-small·Caption).
  `font-weight`는 400~700만 쓴다.
- 간격 스케일 6단계(`--space-1`~`--space-6`).
- 브랜드 강조색(`--brand-primary`) — 이 프로젝트의 색으로 자유롭게 바꾼다.

## 1층 — 하드 규칙 (예외 없음)

### 글자 크기

- 11px 이하 절대 금지. 렌더 후 전체 텍스트를 전수 스캔해 확인한다(권장
  하한은 13px).
- 본문(읽는 텍스트)은 최소 15px, 권장 17px.
- 메인 액션·타이틀은 위계상 충분히 크게 — 칩·캡션처럼 작게 쓰지 않는다.
- 핵심 정보를 caption(13px) 크기에 담지 않는다.
- 문장 안에서 글자 크기를 튀게 바꾸지 않는다.

### 이모지 (권장)

모든 이모지를 Tossface로 렌더하는 것을 권장한다 — 진입 CSS에 이미 배선돼 있다
(`--no-tossface`로 만든 프로젝트는 해당 없음). 아이콘뿐 아니라 본문·데이터·
유저 입력 문자열 안에 섞인 이모지도 전부 포함한다.

### 한글 줄바꿈

한국어 텍스트가 어절 중간에서 끊기지 않는다(`word-break: keep-all` +
`overflow-wrap: break-word`, `src/styles/base.css`가 기본 배선한다).

### 대비·어포던스

- 배경 위 텍스트가 읽힌다. 너무 흐린 회색·배경에 파묻히는 조합을 쓰지 않는다.
- 버튼은 버튼처럼 보인다 — 배경과 구분되는 배경색·테두리·그림자 중 최소
  하나를 갖는다.

### 터치·safe area

- 터치 타겟 최소 44px(시각 크기가 작아도 탭 영역은 44px 확보).
- 하단 CTA는 safe area 여백 34px.

### 광고 배치

- 콘텐츠를 가리지 않는다.
- 첫 화면 콘텐츠(ATF)를 밀어내지 않는다.
- 콘텐츠와 명확히 구분한다(AD 배지 등).
- 하단 탭바가 있으면 광고를 화면 바닥에 고정하지 않는다.
- 클릭 영역이 콘텐츠 클릭 영역을 침해하지 않는다.

### 레이아웃 무결성

- 텍스트가 다른 요소와 겹치지 않는다(음수 마진 특히 주의).
- 요소가 화면 밖으로 잘리지 않는다.
- 의도 없는 여백·정렬 어긋남을 남기지 않는다.
- 이미지 비율을 유지한다.
- 과대한 이미지가 핵심 액션을 밀어내지 않는다.
- 바텀시트엔 닫기 어포던스를 둔다.
- 화면 배경색은 뷰포트 전체를 채운다(`.canvas` 유틸).

### 다크패턴 금지

- 예상치 못한 전면광고 금지.
- 진입 첫 순간을 전면 요소로 막지 않는다 — 가치를 먼저 보여준다.
- 이탈을 가로막지 않는다.
- 탈출로 없는 화면(dead end)을 만들지 않는다.
- 가짜 버튼·닫기 숨김·강제 행동 유도 금지.
- 같은 동작을 하는 CTA를 한 화면에 중복해서 두지 않는다.
- 광고를 콘텐츠인 척 위장하지 않는다.

### 꺾쇠·화살표

- 버튼 안에는 방향 화살표·꺾쇠를 넣지 않는다.
- 이동·진입을 나타내는 꺾쇠는 `>` `‹` `›` 같은 텍스트 문자가 아니라 반드시
  SVG 아이콘을 쓴다. 이 프로젝트가 React 계열이면 `src/components/icons.tsx`,
  vanilla 계열이면 `src/assets/icons/*.svg`의 6종(chevron-right·left·down·
  up·close·search)을 쓴다. 색은 `currentColor`로 부모에서 상속한다.
- 아이콘은 제작자 자신의 세트나 오픈 라이선스 아이콘을 쓴다 — 토스 내부
  아이콘은 외부 제작자용으로 라이선스가 열려 있지 않을 수 있다.

### 상단 네비게이션

앱인토스가 화면 상단에 네비게이션 바(뒤로가기·화면 제목·닫기)를 자동으로
붙인다. 화면 안에 상단 네비바를 직접 그리지 않는다 — 그리면 두 겹으로
겹친다. 콘텐츠는 본문 첫 요소부터 시작하고, 화면 제목·우측 액션이 필요하면
플랫폼 네비로 넣는다.

## 2층 — 권장

- 위계(크기·굵기·색으로 우선순위를 만든다).
- 크기는 정해진 스케일로만.
- 강조색은 절제.
- 정렬(좌측 기준선 통일).
- 간격(같은 그룹은 좁게, 다른 그룹은 넓게 — `--space-*` 스케일).
- 같은 그룹의 컨트롤 크기를 맞춘다.
- 둥근 버튼·카드 권장.
- 주요 CTA는 하단 고정 권장.
- 적절한 입력 컨트롤을 쓴다(긴 선택지는 피커·스피너로).
- 한 화면 정보량을 절제한다.
- 손톱 금지 — radius가 있는 박스에 한쪽 면에만 선·색띠를 넣지 않는다(둥근
  카드에 단색 accent border를 두르는 것도 대표적 AI slop이다). 강조가
  필요하면 4면 균일 테두리·배경 틴트·내부 배지로 한다.
- 그림자(shadow) 절제 — 상시 요소(버튼·카드·입력·리스트 행)에 drop shadow를
  남발하지 않는다. 그림자는 실제로 떠 있는 요소(다이얼로그·시트·툴팁)에만.
- 카드·행의 좌우 여백은 대칭으로.
- TDS-like 컴포넌트는 선택(강제 아님).

정보 구성: 인접한 블록엔 최소 간격을 둔다 / 배경·틴트 박스엔 radius와 사방
padding을 준다 / 단일 목적 화면엔 글로벌 탭바를 넣지 않는다 / 빈 화면을
만들지 않는다(다음 액션을 함께 넣는다).

## 3층 — 이 프로젝트의 개성

- 브랜드색 자유(1층의 대비, 2층의 강조색 절제만 지킨다).
- 본문 폰트 자유(1층의 최소 크기만 준수, Tossface는 이모지에만 권장).
- 일러스트·톤·레이아웃 자유.
- 광고는 억제·위장 대상이 아니다 — 아래 5축으로 "유저가 반기는 광고"를
  설계한다.

| 축 | 질문 |
|---|---|
| 관련성 | 이 유저·이 순간에 진짜 맞는 제안인가 |
| 보상 | 유저가 얻는 이득이 먼저 보이는가 |
| 자기표현 | 공유·참여가 유저를 돋보이게 하는가 |
| 재미 | 행위 자체가 즐거운가 |
| 정직함 | 광고임을 숨기지 않고 당당히 가치를 제시하는가 |

관련성 없는 강매, 기만, 사행성 과장은 광고 가치화가 아니라 착취다. 정직함
축이 무너지면 안 된다.

## 갱신

이 파일은 스캐폴드(`/ait:new`)나 `/ait:design`이 넣는다. 규칙이 오래됐다 싶으면 `/ait:design`을
다시 부른다 — 버전이 다르면 무엇이 바뀌는지 보여주고 승인을 받는다.
