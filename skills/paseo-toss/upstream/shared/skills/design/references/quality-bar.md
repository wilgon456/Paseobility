# 디자인 품질 판정 기준 (quality bar)

design이 산출한 화면·등록 자산이 "괜찮은가"를 **매번 같은 축으로** 판정하기
위한 기준이다. 기준이 없으면 품질은 매 세션 모델의 취향으로 흔들리고, 개선했는지
여부도 잴 수 없다.

## 이 기준의 지위 (정본 구분)

- 이 파일은 **harness가 정의한 판정 기준**이지 앱인토스 공식 디자인 가이드가
  아니다. 공식 가이드의 정본은 공식 문서이며, 조회는 docs MCP로 한다
  (`references/docs-lookup.md`).
- **1층 하드 규칙의 정본은 `render-rules.md`다.** 이 파일의 `차단` 등급 항목은
  그 1층을 화면 단위 판정 항목으로 옮겨 적은 것이다 — 문면이 어긋나면
  `render-rules.md` 쪽이 정본이고, 고치는 방법도 그 파일에 있다.
- 각 항목의 `근거` 열이 출처를 구분한다:
  - **H** — harness 기준(이 파일이 정의). 공식 문서를 대신 주장하지 않는다.
  - **D** — 공식 문서에서 확인해야 하는 항목. 확인 전에는 "공식 규격"이라고
    단정하지 말고 `(문서 확인 필요)`로 남긴다.
  - **W** — 공개 웹 표준(WCAG 등). 출처를 밝히고 인용한다.
- 항목을 추가·수정할 때 근거 없는 수치를 새로 만들지 않는다. 수치가 필요하면
  D로 두고 docs MCP로 확인하거나, 프로젝트가 스스로 정한 값(토큰)으로 돌린다.

## 판정 단위와 등급

- **판정 단위는 화면**이다. 화면 목록이 없으면 먼저 화면 목록부터 확정한다.
- 각 항목의 판정은 셋 중 하나: **통과** / **조정 필요**(사유 1줄 필수) /
  **해당 없음**(사유 1줄 필수).
- 각 항목에는 `등급` 열이 붙어 있다. **`차단`은 조정 필요가 남으면 완료가
  아니고 design이 직접 고쳐야 하는 항목**, **`권장`은 목록으로 남기고 진행할
  수 있는 항목**이다. 등급은 그룹이 아니라 항목에 붙는다 — 한 그룹 안에 두
  등급이 섞인다.
- "아마 괜찮다"로 통과시키지 않는다. 확인할 수단이 없으면 조정 필요가 아니라
  `(확인 필요)`로 적고 사용자에게 무엇을 확인해야 하는지 넘긴다.

## G0 — 브랜드·IP 안전

SKILL.md의 "토스 브랜드·UI 모방 금지" 절이 정의하는 금지 목록을 그대로 판정
항목으로 쓴다. **하나라도 걸리면 나머지 항목을 채점하지 않고 멈춘다**(그 절의
"위반 의심 시 절차"). G0은 유일하게 자동 수정 대상이 아니다 — 대안 선택이
사용자의 것이라 고치지 말고 확인받는다.

G0은 **두 번째** 관문이다 — 같은 목록의 첫 번째 적용은 SKILL.md 실행 순서
0단계(브랜드 체크포인트)이고, 그것은 자산·코드를 만들기 **전에** 통과해야
한다. 여기서 처음 걸린다는 것은 이미 만들어 놓고 채점하고 있다는 뜻이므로,
0단계가 건너뛰어졌다는 사실도 함께 보고한다.

| # | 항목 | 등급 | 근거 |
|---|---|---|---|
| G0-1 | 토스 로고·워드마크(변형 포함)를 아이콘·화면·등록 자산에 쓰지 않았다 | 차단 | H |
| G0-2 | 토스 브랜드 컬러를 미니앱 primary 색으로 채택하지 않았다 | 차단 | H |
| G0-3 | 토스 앱 화면(특히 로그인/인증)의 구성을 복제하지 않았다 | 차단 | H |
| G0-4 | "토스" 상호로 미니앱 자체를 토스 공식 제품처럼 표방하지 않았다 | 차단 | H |
| G0-5 | 토스 전용 본문 서체(`Toss Product Sans` 계열)를 `font-family`·웹폰트·번들 파일 어디로도 쓰지 않았다 — 시스템 폰트 스택이나 라이선스가 명확한 공개 웹폰트를 쓴다 | 차단 | H |
| G0-6 | 화면에 넣은 아이콘·이미지의 출처와 사용 조건을 확인했다 — 제작자 자신의 세트, 오픈 라이선스, 또는 앱인토스가 제공하는 아이콘 라이브러리다. 라이선스가 열려 있는지 모르는 자산(토스 내부 아이콘 포함)은 링크·번들하지 않는다 | 차단 | H |

이모지 서체 `Tossface`는 **G0-5에 걸리지 않는다** — 공개 배포되고 자체
라이선스가 붙어 있어 사용이 허용된다(SKILL.md의 대안 절). 다만 폰트 파일을
직접 번들·재배포하는 경우 라이선스가 저작권 안내 동봉을 요구하므로, 그 경로를
골랐으면 안내가 함께 남아 있는지 본다.

## G3 — 토큰 일관성

| # | 항목 | 등급 | 근거 |
|---|---|---|---|
| G3-1 | 색·타이포·spacing이 이름 있는 토큰으로 정의돼 있다(값이 한 곳에 모여 있다) | 권장 | H |
| G3-2 | 같은 역할의 값이 화면마다 다르지 않다(예: 본문 텍스트 색이 화면별로 제각각이 아님) | 권장 | H |

| G3-7 | 한 문장·한 라벨 안에서 글자 크기가 튀지 않는다 — 강조는 크기가 아니라 weight·색으로 준다 | 차단 | H |

## G7 — 렌더 무결성·시각 안티패턴

생성된 화면이 실제 렌더에서 깨지거나 검토 없이 만들어진 티를 내는 시각 결함
축이다. 심미성 점수화가 아니라 결함 유무 판정이다("이 기준이 하지 않는 것"의
❌ 심미성 점수화와 충돌하지 않는다). 각 항목은 코드에서 재현 가능하게 확인한다.

| # | 항목 | 등급 | 근거 |
|---|---|---|---|
| G7-1 | 텍스트·요소가 서로 겹치지 않고 화면 밖으로 잘리지 않는다(음수 마진·고정 높이 넘침을 확인한다) | 차단 | H |
| G7-2 | 화면 안 이미지가 원본 종횡비를 유지한다 — 늘리거나 눌러 맞추지 않는다(등록 자산의 같은 규칙은 G2-3) | 차단 | H |
| G7-3 | 방향·행동 아이콘(chevron·화살표 등)을 텍스트 글리프(`>`·`»`)로 때우지 않는다 — 인라인 SVG로 넣고 색은 `currentColor`로 잇는다 | 차단 | H |
| G7-4 | 카드·버튼처럼 네 변이 동일한 형태인 요소에 한쪽 변만 다른 색으로 칠한 보더를 쓰지 않는다 — 둥근 모서리에서는 편측 보더가 곡률과 이어지지 않아 렌더가 어긋나 보인다. 강조는 균일한 사방 테두리·배경색 변화·별도 배지처럼 카드 전체에 고르게 적용되는 방식으로 표현한다 | 권장 | H |
| G7-5 | 상시 요소(카드·버튼·입력·리스트 행)에 드롭 섀도가 있으면 목록으로 짚는다 — 뜬 요소(다이얼로그·시트·툴팁·드롭다운)와 달리 띄움 위계가 없는 곳의 섀도는 계층 관계를 흐리게 만든다 | 권장 | H |
| G7-6 | 한국어 텍스트 블록에 `word-break: keep-all`이 적용돼 어절 중간에서 줄이 바뀌지 않는다 | 차단 | H |

## G8 — 다크패턴·광고

낮다"가 아니라 "사용자에게 해롭다"에 해당하므로 전 항목이 차단이다. 광고가
없는 앱은 광고 항목을 해당 없음으로 판정한다.

## 완료 판정 규칙

1. **G0에 조정 필요가 1건이라도 있으면 즉시 중단** — 채점을 이어가지 않고
   사용자에게 해당 항목을 알린 뒤 확인을 받는다. G0은 고쳐서 넘기지 않는다.
2. **`차단` 등급 항목에 조정 필요가 남아 있으면 design은 "완료"가 아니다** —
   어느 화면의 어느 항목인지 짚고, 목록으로 넘기지 말고 렌더 단계로 돌아가
   고친 뒤 같은 항목을 재판정한다(G0은 규칙 1을 따른다).
   차단 항목을 가진 그룹: G0·G1·G2·G3·G4·G7·G8.
3. **`권장` 등급은 완료를 막지 않는다.** A·B 모드에서는 목록을 먼저 내밀지
   않고, 있으면 완료 블록 안에 "다듬을 여지 M건 더 있어요" 한 줄로만 둔다. 사용자가 원하면
   펼친다.
4. **수정 루프는 같은 항목에 대해 최대 2회**까지 돈다. 2회로 안 풀리면 계속
   고치지 말고 무엇이 걸렸는지 적어 넘기고, 그 항목을 `(확인 필요)`로 남긴다.
5. `(확인 필요)`(판정 수단 없음) 항목은 조정 필요와 별도로 세어 완료 안내에
   그대로 노출한다 — 조용히 통과시키지 않는다.
6. D 근거 항목을 공식 규격으로 단정하려면 docs MCP 조회 결과가 있어야 한다.
   조회하지 않았으면 `(문서 확인 필요)`로 남긴다.

## 자기 점검 출력 형식

**기본 출력은 판정표가 아니다.** 모드 A·B의 완료 안내는 바뀐 파일과 변경
사실(예: 본문 13px → 15px), 남은 차단 항목, 사용자가 정해야 할 것만 말한다.
아래 화면별 표와 요약 줄은 **모드 C(사용자가 점검을 요청한 경우)이거나 사용자가
물었을 때만** 인쇄한다. 규칙이 왜 있는지는 설명하지 않는다.

존중 모드에서는 G3를 프로젝트 자체 토큰 기준으로 채점하고(이 문서의 기본 토큰이
아니다), 1-3·1-9에 해당하는 항목은 권장으로 내려 요청이 없으면
표에 싣지 않는다.

요청받아 인쇄할 때 채점 결과는 화면별 표 + 요약 한 줄로 고정한다. 형식을
고정해야 세션 간 비교가 가능하다.

```
품질 점검 (quality bar)

  홈
    G1 컨테이너   통과
    G3 토큰       조정 필요 — 카드 배경이 #F5F5F5 하드코딩, surface 토큰 없음 (권장)
    G4 구조·조작  통과
    G5 상태       조정 필요 — 목록 0건일 때 빈 상태 미정의 (권장)
    G6 카피       통과
    G7 렌더       통과
    G8 다크패턴   해당 없음 — 광고·전면 요소 없음
  상세
    G1 컨테이너   조정 필요 — 커스텀 헤더가 컨테이너 헤더와 이중 (차단)
    G3 토큰       통과
    G4 구조·조작  확인 필요 — 대비비를 잴 색상값 미확정
    G5 상태       통과
    G6 카피       통과
    G7 렌더       통과
    G8 다크패턴   해당 없음 — 광고·전면 요소 없음

  자산 (G2)       통과 — 필수 5종 규격 일치
  브랜드 (G0)     통과

  요약: 차단 1건 / 권장 2건 / 확인 필요 1건 — G1-3 미해소가 있어 완료 보류
```

차단 항목을 고쳤으면 같은 표를 다시 인쇄해 해소됐음을 보인다. 자동 수정한
항목은 무엇을 어떻게 바꿨는지 한 줄로 함께 적는다.

## 이 기준이 하지 않는 것

- ❌ 심미성 점수화 — "예쁨"을 숫자로 매기지 않는다. 이 기준은 **재현 가능한
  항목**만 다룬다.
- ❌ 공식 디자인 가이드 대체 — D 근거 항목은 문서가 정본이고 이 파일은 그것을
  조회하도록 가리킬 뿐이다.
- ❌ 3층 판정 — 브랜드색·폰트·톤·레이아웃 취향은 제작자의 것이라 항목으로
  올리지 않는다(`render-rules.md` 3층).

**판정에서 멈추는 것도 여기 없다.** `차단` 등급에 조정 필요가 남으면 design은
목록만 넘기지 않고 렌더 단계로 돌아가 화면 코드를 직접 고친 뒤 재판정한다
(SKILL.md 4단계). 이 파일이 정의하는 것은 *무엇을* 고쳐야 하는가이고, *어떻게*
고치는가는 `render-rules.md`다.
