# 경량 PRD 템플릿 + 작성 예시

`/ait:plan`이 `PRD.md`로 남기는 문서의 정본 형식이다. 미니앱 v1 한 개를 만드는 데
필요한 최소 항목만 담는다 — 일반 PRD의 시장 분석·KPI 트리·마일스톤은 넣지 않는다.

**섹션 9개는 고정이고, 순서도 고정이다.** 내용이 없는 섹션은 지우지 말고
`(없음)` 또는 `(확인 필요)`로 남긴다 — 빈칸 자체가 다음 디스커션의 질문거리다.

## 템플릿

````markdown
# PRD — <앱 한 줄 이름>

작성: /ait:plan · <YYYY-MM-DD>

## 1. 한 줄 정의

<누가> <언제> <무엇을> 한다.

## 2. 사용자와 문제

- 핵심 사용자: <한 명으로 특정>
- 지금 겪는 불편: <현재 방식과 그 한계>
- 이 미니앱이 바꾸는 것: <한 문장>

## 3. 핵심 여정 (3~5스텝)

1. 진입: <어디서 들어오나>
2. <핵심 행동 1>
3. <결과 확인>
4. 이탈/재방문: <다시 오는 이유>

## 4. 화면 흐름

| 화면 | 목적 | 전환 |
|---|---|---|
| <이름> | <한 줄> | <다음 화면 / 뒤로> |

- 뒤로가기: <swipe-back·PageHeader에서 어떻게 되나>
- 빈 상태/로딩: <처음 들어온 사용자가 보는 것>

## 5. SDK 도메인·권한

| 도메인 | 왜 필요한가 | 권한 | 거부 시 동작 |
|---|---|---|---|

- 권한 없이도 되는 최소 기능: <무엇>

## 6. 데이터

- 저장 위치: <로컬(storage) / 서버 / 없음>
- 서버가 필요한 부분: <있으면 명시 — harness 범위 밖, 직접 준비>
- 개인정보: <수집하는 것 / 안 하는 것>

## 7. 수익화

- 모델: <없음 / IAP(디지털 재화) / 광고(IAA) / 토스페이 결제>
- 트리거되는 약관: <위 모델에 따라>
- v1 포함 여부: <포함 / 이후>

## 8. 검수 리스크

| 항목 | 상태 | 대응 |
|---|---|---|
| 카테고리(게임/비게임) | <선택> | <실제 서비스와 일치하는가> |
| 권한 거부 fallback | <있음/없음> | <> |
| 금지 패턴(iframe 등) | <해당 없음/해당> | <> |
| 프로모션·사행성 요소 | <없음/있음> | <> |

## 9. 범위

- v1에 넣는 것: <목록>
- v1에서 뺀 것: <목록 — 뺀 이유 한 줄>
- 완료 기준: <이게 되면 v1 완료>
````

## 작성 예시 (가상)

아래는 **실존하지 않는 가상의 미니앱**으로 채운 예시다. 형식 감을 잡는 용도이며,
그대로 복사해 쓰지 않는다.

````markdown
# PRD — 모임 출석 체크

작성: /ait:plan · 2026-08-10

## 1. 한 줄 정의

동호회 총무가 모임 당일 현장에서 참석자를 한 번에 체크한다.

## 2. 사용자와 문제

- 핵심 사용자: 주 1회 오프라인 모임을 운영하는 소모임 총무
- 지금 겪는 불편: 단톡방에 이름을 받아 적고 나중에 엑셀로 옮긴다. 현장에서
  누가 왔는지 실시간으로 모른다.
- 이 미니앱이 바꾸는 것: 모임 장소에서 열면 참석 체크가 그 자리에서 끝난다.

## 3. 핵심 여정 (3~5스텝)

1. 진입: 총무가 모임 시작 직전 미니앱을 연다.
2. 오늘 모임을 만들고(이름·장소) 현재 위치를 기록한다.
3. 참석자 이름을 탭해 체크한다. 체크할 때 짧은 진동 피드백.
4. 재방문: 다음 모임 때 지난 명단이 그대로 떠서 체크만 하면 된다.

## 4. 화면 흐름

| 화면 | 목적 | 전환 |
|---|---|---|
| 모임 목록 | 지난 모임과 오늘 모임 | → 출석 체크 / → 명단 관리 |
| 출석 체크 | 명단 탭으로 참석 표시 | ← 목록 |
| 명단 관리 | 멤버 추가·삭제 | ← 목록 |

- 뒤로가기: 목록이 루트. 체크·관리 화면에서 swipe-back 하면 목록으로
  돌아오고, 루트에서의 swipe-back은 미니앱 종료다.
- 빈 상태: 모임이 하나도 없으면 "첫 모임 만들기" 하나만 보여준다.

## 5. SDK 도메인·권한

| 도메인 | 왜 필요한가 | 권한 | 거부 시 동작 |
|---|---|---|---|
| auth | 총무 본인 확인, 기기 바꿔도 명단 유지 | — | 로그인 없이 로컬 명단만 사용 |
| location | 모임 장소를 자동 기록 | geolocation | 장소를 직접 입력 |
| storage | 명단·출석 기록 로컬 저장 | — | — |
| navigation | 목록 ↔ 체크 ↔ 관리 전환 | — | — |
| haptic | 체크 시 촉각 피드백 | — | — |

- 권한 없이도 되는 최소 기능: 명단 관리 + 출석 체크(위치 없이)

## 6. 데이터

- 저장 위치: 로컬(storage)
- 서버가 필요한 부분: 총무 여러 명이 같은 모임을 공유하는 기능 — v1에서 뺀다
- 개인정보: 멤버 이름만 사용자가 직접 입력. 연락처는 읽지 않는다.

## 7. 수익화

- 모델: 없음
- 트리거되는 약관: BIZ_WORKSPACE(기본), TOSS_LOGIN(auth 사용)
- v1 포함 여부: 해당 없음

## 8. 검수 리스크

| 항목 | 상태 | 대응 |
|---|---|---|
| 카테고리(게임/비게임) | 비게임 | 비게임 출시 가이드 확인 필요 |
| 권한 거부 fallback | 있음 | 위치 거부 시 장소 직접 입력 |
| 금지 패턴(iframe 등) | 해당 없음 | 외부 페이지 임베드 없음 |
| 프로모션·사행성 요소 | 없음 | — |

## 9. 범위

- v1에 넣는 것: 모임 생성, 명단 관리, 출석 체크, 로컬 저장
- v1에서 뺀 것: 총무 간 공유(서버 필요), 통계 화면(핵심 여정 밖)
- 완료 기준: 모임을 만들고 명단 5명을 체크한 뒤 앱을 껐다 켜도 기록이 남는다.
````

## 디스커션 진행 규칙

- 섹션을 순서대로 한 번에 하나씩 채운다. 9개를 한꺼번에 묻지 않는다.
- 사용자가 모르는 항목은 에이전트가 **초안을 제안하고 확인받는다** — 빈칸으로
  넘기지 않되, 확정된 것처럼 쓰지도 않는다.
- 5번(도메인·권한)·7번(약관)은 SKILL.md의 카탈로그 매핑 결과를 그대로 옮긴다 —
  PRD와 계획 블록이 서로 다른 값을 갖지 않게 한다.
- 8번(검수 리스크)에서 확신이 없는 항목은 docs MCP(`searchDocumentation`/
  `askQuestion`)로 확인하고, 확인이 안 되면 `(확인 필요)`로 남긴다.
