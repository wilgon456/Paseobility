# Coordinated updates

Apply this procedure only to the requested products and computers. Updating Paseo and updating a manager repository are distinct operations. A manager update does not authorize running every managed CLI updater or deleting user data.

1. Establish each target's platform/architecture and whether its daemon is Desktop-managed, standalone or containerized. Check the official latest stable release at execution time; do not keep 0.11.2 as a universal target. Read target repository instructions before changing a checkout. Preserve uncommitted work and existing schedule/PATH/configuration state.
2. Prepare the appropriate official artifact locally on the target, verify the release's published hash and available platform signature, and keep the current install as a rollback copy. Do not depend on a temporary controller HTTP server after queuing an idle install. An unsigned official artifact must not be described as signed.
3. Check agent lifecycle and pending work. For a user-selected "after this task" update, install a host-local one-time watcher with a bounded polling interval (for example 30 seconds), no automatic repeat after success, and a completion/error log. It must fail closed when listing agents or parsing their lifecycle states fails. Preserve running/starting/interrupting agents and attention/permission waits. Check the specific requested task as well as other active work; unknown states do not mean idle. Scope the watcher to a unique maintenance job and keep its script/private state outside the repository.
4. When idle, stop only the selected app/daemon as needed for the chosen install topology. Replace/relaunch and verify a fresh daemon handshake. Desktop may start a new daemon asynchronously: wait for its published readiness before issuing lifecycle commands. A transient `DAEMON_NOT_RUNNING` during startup is not proof installation failed; inspect installed version and live runtime before retrying.
5. Verify app/CLI and daemon versions separately. For a manager, compare deployed files against the intended source manifest, run its doctor, and read back preserved task/settings state. Keep version mismatch or unavailable status explicit. A restart acknowledgment, installer exit 0 or passing source tests alone is insufficient.
6. Remove only this operation's one-time watcher after verified success. Retain logs/backups. Report complete, pending, failed or unreachable separately for each target. A queued update remains pending until readback verifies the new version.

For macOS use a one-time LaunchAgent with `RunAtLoad: true`, `KeepAlive: false`; avoid a repeating launch mechanism that reruns the installer. For Windows preserve scheduled task principal/settings and use host paths. Linux/container updates need their installation-specific process manager. Do not copy a fixed PID, path or restart command from an old run.
