# Paseo 커스텀 기능 로드맵

이 문서는 단순한 프롬프트 기반 슬래시 스킬이 아니라 Paseo의 제어 계층에
포함할 만한 아이디어를 정리한다. 아직 탐색 단계이며, Paseobility가 Paseo를
수정하거나 별도 포크로 유지하겠다는 의미는 아니다.

## 기능 구분 원칙

- 특정 provider의 작업 방식이나 반복 지침은 스킬로 유지한다.
- 결과가 결정적인 프로젝트 명령은 Paseo Workspace Script로 유지한다.
- 지속적인 데몬 상태, 여러 호스트의 정보, 모바일 UI 또는 공통 권한 경계가
  필요한 기능만 Paseo 본체 기능으로 검토한다.
- Paseo를 장기간 별도 포크하기보다 업스트림과 호환되는 확장 기능이나
  기여 방식을 우선한다.

## 로드맵

### 1. 여러 호스트의 상태 확인과 작업 인계

목표는 한 호스트가 다른 호스트를 통제하지 않으면서, 사용자가 서로 독립된
여러 Paseo 호스트의 상태를 파악하고 검토한 작업 요약을 옮길 수 있게 하는
것이다.

검토할 수 있는 범위는 다음과 같다.

1. 기존 클라이언트에서 호스트 상태와 사용 가능한 기능을 읽기 전용 카드로
   보여준다.
2. 호스트 전환은 사용자가 직접 수행하며, 에이전트가 원격 호스트를 선택하지
   않는다.
3. 저장소 식별자, commit, 결정 사항, 테스트, 남은 작업 및 산출물 참조를 담은
   검토 가능한 작업 인계 패킷을 내보낸다.
4. 다른 호스트에서 패킷을 가져오면 사용자가 검토하고 시작할 수 있는 로컬
   초안을 만든다.

여러 호스트를 넘나드는 에이전트 생성, 원격 명령 전달, 자동 환경 복구,
데몬을 넘는 부모·서브에이전트 관계 및 자동 호스트 선택은 명시적으로 범위에서
제외한다. 각 컴퓨터는 운영체제, 인증 정보, 도구, 저장소, 로컬 데이터 및
provider 동작이 다를 수 있다. 중앙 통제 기능을 추가하면 이러한 차이가 크고
위험한 분산 실행 표면으로 확대된다.

### 2. 자동화 훅

`agent.completed`, `agent.failed`, `permission.requested`, `schedule.failed`처럼
작고 감사 가능한 이벤트 집합을 제공한다. 초기에는 실행 시간 제한, 중복 방지
키, 로그 및 명시적인 권한을 적용한 명명된 Workspace Script와 로컬 알림만
허용한다.

### 3. 네이티브 산출물

에이전트가 파일을 지속적으로 보관할 산출물로 지정하고 메타데이터, 체크섬,
미리보기, 보관 기간 및 다운로드 권한을 관리할 수 있게 한다. 먼저 Paseo의
기존 암호화 원격 연결을 이용하는 호스트 로컬 저장 방식으로 시작한다. 이후
private Git 저장소를 저장 어댑터로 추가할 수 있으며, 이 경우 `paseo-share`는
유일한 산출물 전송 수단이 아니라 Git 저장 어댑터 역할로 발전할 수 있다.

### 4. 다른 환경에서 작업 재개

목표, 저장소 식별자, commit, 결정 사항, 테스트, 남은 작업 및 산출물 참조를
포함하는 재개 패킷을 내보낸다. 다른 환경에서 패킷을 가져오면 새 에이전트를
바로 실행하지 않고 사용자의 로컬 검토가 필요한 초안을 만든다. 실행 중인
provider 세션을 이동하거나 검토하지 않은 patch를 전송하지 않는다.

### 5. 확장 기능 인터페이스

실제 사용 사례가 안정된 다음 자동화 훅과 산출물 계약을 제한된 확장 형식으로
발전시킨다. 제한 없이 Paseo 프로세스 안에서 실행되는 플러그인보다 선언형
명령, 이벤트, 저장 어댑터 및 UI 카드를 우선한다.

## 폐기한 방향: 여러 호스트의 원격 실행

직접적인 여러 호스트 간 작업 전달은 검토 후 이 로드맵에서 폐기했다. 여러
호스트를 통합 지휘하는 기능은 분산 시스템에 해당하며, 서로 다르게 설정된
개인용 컴퓨터에서 얻는 편의보다 장애 및 보안 부담이 크다. 의사결정 기록을
위해 주요 위험을 다음과 같이 남긴다.

- **식별과 신뢰:** 만료되거나 오래된 페어링 인증, 호스트 이름 변경, 키 교체,
  중복된 호스트 이름 및 통제 역할을 하는 호스트의 침해 위험이 있다.
- **버전 차이:** 컴퓨터마다 클라이언트, 데몬, CLI, MCP 및 provider 어댑터가
  서로 다른 기능과 계약을 제공할 수 있다.
- **프로젝트 식별:** 같은 저장소라도 경로, 원격 저장소, fork, 브랜치,
  submodule, Git LFS 상태, 대소문자 처리 및 줄바꿈 방식이 다를 수 있다.
- **공유되지 않은 로컬 상태:** commit하지 않은 파일, push하지 않은 commit,
  무시된 파일, 로컬 데이터베이스, 비밀 정보 및 생성된 산출물이 대상 컴퓨터에
  존재하지 않을 수 있다.
- **Provider 환경 차이:** 요청한 provider, 모델, 모드, 로그인, 할당량, MCP
  서버, 브라우저 호스트 또는 스킬을 원격 컴퓨터에서 사용할 수 없을 수 있다.
- **분산된 실행 생명주기:** 네트워크 연결이 끊기면 생성 결과를 확정할 수 없고,
  중복 실행, 고아 workspace, 누락된 완료 통지 또는 잘못된 클라이언트에 표시된
  권한 요청이 발생할 수 있다.
- **동시 쓰기:** 두 호스트가 같은 브랜치를 수정하거나 push할 수 있으며, 서로
  충돌하는 migration 또는 배포 작업을 동시에 실행할 수 있다.
- **확대된 보안 범위:** 원격 full-access 실행은 사고 범위를 넓히고, patch와
  프롬프트를 전송하는 과정에서 비밀 정보가 섞일 수 있다.
- **부분적인 정리:** workspace는 생성됐지만 에이전트 시작은 실패할 수 있다.
  이때 실패한 요청이 소유한 리소스만 정확하게 제거하기 어렵다.

## 안전한 첫 번째 목표

첫 번째 목표는 정보를 제공하고 사용자가 직접 판단하게 하는 기능으로
제한한다.

- 이미 연결된 각 호스트의 온라인 상태, Paseo 버전, 운영체제 및 사용 가능한
  provider를 인증 정보 노출이나 호스트 통제 없이 보여준다.
- 사용자는 Paseo의 기존 연결 방식을 이용해 호스트를 직접 전환한다.
- 비밀 정보, 무시된 파일, commit하지 않은 patch, 인증 자료 또는 실행 가능한
  내용을 포함하지 않는 작고 검토 가능한 작업 인계 문서를 내보낸다.
- 문서를 가져오면 초안으로만 연다. 대상 호스트가 자신의 저장소와 환경을 직접
  검사하고, 사용자가 로컬 에이전트 실행을 명시적으로 시작한다.
- 지속적으로 보관할 결과물은 네이티브 산출물 기능이나 `paseo-share`를 통해
  별도로 공유한다.

이 경계는 각 컴퓨터의 장애 범위를 독립적으로 유지한다. 한 컴퓨터가 고장 나거나
침해되거나 오프라인이거나 다르게 설정되어 있어도 다른 호스트로 명령을 전달할
수 없다.
