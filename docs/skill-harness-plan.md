# 스킬 카탈로그와 하네스 계획 (초안)

작성: 2026-11-10 · 기준: Paseobility v3.0.0, Paseo 0.15.4, 맥미니 1대 실측
상태(2026-11-11): 이름 변경, `ps` 카탈로그, `ps-plan`, `ps-write`는 v3.0.0으로 `main`에 들어갔어요(PR #58). 나머지는 계획 단계예요.

## 0. 목표와 비목표

**목표**
- Paseo 에이전트가 어떤 프로바이더(Claude, Codex, OpenCode)로 떠도, Claude 기본 앱이나 Hermes Agent보다 **적은 상시 토큰으로 더 많은 스킬**을 쓸 수 있게 해요.
- 리서치, 디자인, 기획, 작성, 코딩 다섯 영역이 같은 규칙으로 움직이고, 끝날 때 검증 증거를 남기게 해요.
- "더 유능하다"를 느낌이 아니라 숫자로 확인해요(5절).

**비목표**
- claude.ai 커넥터나 Codex 앱 전용 플러그인을 다른 프로바이더로 옮기는 일. 계정에 묶여 있어요.
- 네이티브 앱 UI 재현.
- 스킬 자동 수정. Hermes가 만든 스킬을 Paseobility가 고치지 않아요. 제안만 해요.
- 원격 스킬 라이브러리 검색. `paseo-skillhub`은 검색만 되고 맞는 스킬을 못 가져와서 쓰지 않아요. 이 계획은 이미 가진 스킬만 다뤄요.

## 1. 현재 상태 (실측)

| 위치 | 스킬 수 | 상시 실리는 이름+설명 | 비고 |
|---|---|---|---|
| Claude `~/.claude/skills` | 50 | 15,692자 (약 5천 토큰) | 플러그인 스킬은 별도로 더 실려요 |
| Paseo 공용 `~/.agents/skills` | 31 | 11,434자 (약 4천 토큰) | Hermes도 이 폴더를 읽고 16개를 꺼 둠 |
| Codex `~/.codex/skills` | 31 | 7,927자 (약 2.5천 토큰) | |
| Hermes `~/.hermes/skills` | 56 | 19,261자 (약 6천 토큰) | 12개는 Hermes가 직접 만든 것 |
| OpenCode | 0 | — | |

토큰 수는 글자 수에서 어림한 값이에요. 정확한 값은 P0에서 다시 재요.

- Claude, Codex, 공용 폴더를 합치면 60종인데 세 곳 모두에 있는 건 2개뿐이에요.
- Hermes가 만든 12개는 실사용이 많아요(`international-sales-readiness` 29회, `structured-data-markup` 26회 등). 지금 Paseo 에이전트는 이걸 못 써요.
- MCP 도구는 프로바이더끼리 겹치는 게 없어요(Claude `rhwp`는 연결 실패, Codex 3개, OpenCode 1개).
- `~/.codex/skills/humanize-korean`은 `references`가 없는 경로를 가리켜 참조 문서 3개를 못 읽어요.

### 첫 턴 고정 토큰 (2026-11-10 실측, 같은 폴더에서 한 단어 응답)

| 환경 | 고정 토큰 | 방법 |
|---|---|---|
| Hermes Agent | 약 1.9만 (추정) | `hermes prompt-size`: 시스템 프롬프트 39,288자 + 도구 정의 21개 32,306바이트. 글자 수에서 어림 |
| Claude Code 직접 실행 | 40,876 | API가 돌려준 사용량 |
| Paseo 안의 Claude | 45,904 | 같은 방법. 직접 실행보다 5,028(12%) 많음 |
| Codex | 측정 못 함 | 계정 크레딧 소진으로 실행 실패 |

Claude Code 고정 토큰의 구성(haiku로 항목을 꺼 가며 측정, 합계 39,413):

| 항목 | 토큰 | 비중 |
|---|---|---|
| 기본 시스템 프롬프트와 내장 도구 | 약 24,600 | 62% |
| MCP 커넥터와 플러그인 도구(이름, 안내문) | 약 9,500~11,700 | 24~30% |
| 스킬 목록 전체(개인 50개 + 플러그인·내장) | 약 3,000~5,300 | 8~13% |

두 항목을 따로 껐을 때와 같이 껐을 때의 차이가 맞아떨어지지 않아 범위로 적었어요.

**이 측정이 계획에 주는 뜻**
- 스킬 목록을 반으로 줄여도 Claude에서는 2천 토큰 안팎(전체의 4~5%)이에요. 카탈로그의 주된 효과는 토큰 절감이 아니라 **어느 프로바이더에서든 115개에 닿는 것**이에요.
- 토큰을 가장 많이 줄일 수 있는 곳은 MCP 커넥터예요(약 1만). 3.5절 도구 트랙을 P2로 앞당겨요.
- Hermes는 스킬 68개를 5,460자로 싣고 있어요. 스킬 색인만 보면 이미 Claude보다 훨씬 촘촘해요.
- Paseo가 Claude에 더하는 5천 토큰(Paseo 도구 이름, 추가 지침)도 줄일 대상이에요.

### 세 환경이 스킬을 싣는 방식

| | Claude 기본 앱 | Hermes Agent | 이 계획의 목표 |
|---|---|---|---|
| 스킬 설명 | 설치된 것 전부 상시 | 전부 상시(`<available_skills>`) | 고정 스킬만 상시, 나머지는 검색 |
| 스킬 본문 | 호출 시 | `skill_view` 호출 시 | 검색 후 원본을 직접 읽기 |
| 도구 정의 | 이름만 상시, 정의는 검색 | 플랫폼별 도구 묶음 | P0에서 프로바이더별 실측 후 결정 |
| 사용 기록·학습 | 없음 | 사용 횟수, 패치 이력 | 사용·실패 기록, 개선 제안 |
| 다른 에이전트의 스킬 | 못 씀 | `external_dirs`로 일부 | 모든 출처를 한 목록으로 |

둘 다 스킬 설명은 전부 상시로 실어요. 스킬 수가 늘수록 비용이 같이 느는 구조라, 여기가 앞설 수 있는 지점이에요.

## 2. 설계 원칙

1. **세 단계로 싣기.** 상시(고정 스킬 설명) → 필요 시(스킬 본문) → 본문이 가리킬 때(참조 문서, 스크립트).
2. **복사하지 않기.** 목록은 원본 경로만 가리켜요. Hermes가 스킬을 고치면 다음 사용부터 바로 반영돼요.
3. **놓치는 비용이 더 커요.** 설명 100토큰 아끼려다 맞는 스킬을 못 찾으면 손해예요. 그래서 검색 품질을 테스트로 묶어요.
4. **단계마다 전후 숫자.** 측정 스크립트 없이 "줄었다"고 쓰지 않아요.
5. **개인 정보는 저장소 밖.** 목록, 출처 설정, 사용 기록은 `~/.paseobility/catalog/`에만 둬요.

## 3. 구성

### 3.1 스킬 카탈로그

`skills/ps/scripts/skill-catalog.js` (Node 20+, 의존성 없음, `paseo-share.js`와 같은 방식).

| 명령 | 하는 일 | 출력 크기 |
|---|---|---|
| `list` | 스킬마다 `이름 — 설명 앞 110자` 한 줄 | 115개 기준 11,668자 |
| `list --names` | 이름만 | 115개 기준 1,775자 |
| `path <이름>` | 원본 `SKILL.md` 경로와 주의 사항 | 한두 줄 |
| `conflicts` | 같은 이름인데 내용이 다른 사본, 깨진 참조 | — |
| `budget` | 출처 폴더별 상시 글자 수와 스킬별 순위 | — |

- **색인 파일을 두지 않아요.** 실행할 때마다 출처 폴더를 바로 훑어요. 스킬이 백여 개라 충분히 빠르고, 낡은 색인이 생기지 않아요.
- 사용 기록(`log`)은 P5에서 넣어요.
- **고르는 건 스크립트가 아니라 에이전트예요.** 스크립트는 목록만 내주고, 에이전트가 목록을 읽고 하나를 골라 원본을 읽어요. 설명이 상시로 실려 있을 때 모델이 하는 판단과 같은 판단을, 필요한 순간에만 하는 거예요.
- **키워드 검색은 쓰지 않아요.** 2026-11-10 시험에서 한국어 요청 5개 중 4개가 키워드로는 하나도 안 걸렸어요. 설명이 대부분 영어라서예요. `paseo-skillhub`이 맞는 스킬을 못 가져온 것과 같은 유형의 실패예요.
- **시험 결과**: 같은 날, 목록 파일만 받은 새 에이전트가 한국어 요청 12개(그중 2개는 "스킬 불필요")에서 12개 모두 맞게 골랐어요. 표본이 작고 "목록을 보라"고 시킨 조건이라, 고르는 정확도만 확인한 거예요. P1에서 30개로 다시 재요.
- **출처**: `~/.hermes/skills`, `~/.codex/skills`, `~/.claude/skills`, `~/.agents/skills`, 개인 스킬 보관소(3.6절). 없는 폴더는 건너뛰어요.
- **주의 사항 표시**: Hermes 전용 도구를 쓰는 스킬, 깨진 참조, 이름이 비슷한 스킬(`humanize-korean`과 `humanizer`)을 한 줄로 알려요.

### 3.2 진입점: `ps-` 이름

| 입력 | 동작 | 설치 |
|---|---|---|
| `/ps <하고 싶은 일>` | 목록에서 맞는 스킬을 골라 읽고 실행. 없으면 없다고 말하고 그냥 진행 | 신설 |
| `/ps list` | 쓸 수 있는 스킬 보기 | `ps`에 포함 |
| `/ps-plan <내용>` | 기획 하네스 | 신설 |
| `/ps-write <내용>` | 작성 하네스 | 신설 |

- 새로 설치하는 스킬은 `ps`, `ps-plan`, `ps-write` 세 개예요. 설명은 각각 50단어 이하라 상시로 늘어나는 양은 합쳐서 150단어 이하예요.
- 사용자가 `/ps`를 직접 치면 "에이전트가 목록을 안 찾아보는 문제"가 생기지 않아요. 안 쳤을 때를 위해 하네스가 시작할 때 목록을 한 번 확인해요.
- 기존 12개도 v3.0.0에서 `ps-god`, `ps-design`처럼 바꿨어요. Paseo 자체 스킬(`paseo-advisor`, `paseo-loop` 등)은 그대로라 접두사로 구분돼요.
- 스킬 이름만 바꿨어요. `paseo-share.js` 파일명, `paseo_share` 저장소, `ps-multi`의 등록부·캐시·터미널 이름은 그대로라 기존 데이터가 계속 동작해요.
- Paseobility 플러그인 피커는 고정 12개 대신 카탈로그 전체를 보여줘요. 설치 안 된 스킬을 고르면 원본 경로 참조를 붙여요.

### 3.3 고정과 내림

| 구분 | 기준 | 예 |
|---|---|---|
| 고정(설치 유지) | 자주 쓰거나, `/이름`으로 부르거나, 자동으로 걸려야 함 | `paseo`, 다섯 하네스, `ps-browser`, `ps-share` |
| 내림(목록만) | 가끔 쓰고, 검색으로 찾아도 충분함 | KBO·로또·우편번호, Cloudflare 계열 중 안 쓰는 것, `ps-toss` |

- 내림은 프로바이더가 제공하는 비활성화 설정을 먼저 써요(Hermes는 `skills.disabled`). 없으면 폴더를 보관 위치로 옮기고 복구 명령을 남겨요.
- 다른 설치 도구가 관리하는 스킬(k-skill의 `.skill-lock.json`, Cloudflare)은 옮기면 업데이트가 깨질 수 있어서 비활성화 설정이 될 때만 내려요.
- 무엇을 내릴지는 P0의 사용 기록을 보고 항목별로 승인받아요.

**잠정 목표**: Paseo 안의 Claude 첫 턴 45,904 → 35,000 토큰 이하(스킬 약 2천 + 커넥터·도구 약 9천 절감), 쓸 수 있는 스킬 50개 → 약 115개. 커넥터를 얼마나 끌 수 있는지 확인한 뒤 확정해요.

### 3.4 하네스 다섯 개

| 영역 | 스킬 | 상태 | 검증 증거 |
|---|---|---|---|
| 리서치 | `ps-research` | 있음 | 출처 등급이 붙은 인용 |
| 디자인 | `ps-design` | 있음 | `design-check` 보고서, 스크린샷 |
| 코딩 | `ps-god` | 있음, 유지 | 테스트·실행 출력 |
| 기획 | `ps-plan` | 신설 | 검증 가능한 수용 기준, 미결정 목록 |
| 작성 | `ps-write` | 신설 | 독자 기준 점검, 한국어 문체 점검 |

코딩 하네스는 새로 만들지 않아요. `ps-god`와 겹치고, 프로바이더 기본 리뷰 기능이 이미 있어요.

**공통 규칙** (다섯 개가 한 묶음으로 느껴지게 하는 부분)
1. 접수: 목표, 수용 기준, 제약을 5줄 이내로. 막힐 때만 질문.
2. 전문 스킬 확인: 목록 1회.
3. 영역별 방법으로 실행.
4. 증거로 검증. 증거가 없으면 완료라고 쓰지 않음.
5. 보고: 휴대폰에서 읽히는 요약과 산출물 경로. 남은 일이 있으면 이어받을 지점.

**토큰 규칙**
- `SKILL.md` 120줄 이하, 설명 50단어 이하. 무거운 내용은 `references/`에 두고 조건이 맞을 때만 읽어요.
- `ps-plan`, `ps-write`는 `ps-god`처럼 명시적으로 부를 때만 동작해요.
- 하네스끼리는 내용을 복사하지 않고 파일 경로를 넘겨요(리서치 → 기획 → 코딩).

**`ps-write`**: `humanize-korean`의 규칙과 참조 문서를 흡수해요. 10월 28일에 작성 스킬을 뺀 이유가 "영어 전용 검사"였는데, 한국어 기준으로 만들면 그 이유가 사라져요.

### 3.5 도구(MCP) 트랙

- 점검: 프로바이더별 MCP 목록, 연결 실패, 미인증을 `paseobility-doctor`에 추가.
- 인증 도우미: Paseo 터미널을 열어 로그인 명령을 띄우고 사용자가 OAuth를 마침.
- 동기화: 승인한 MCP 정의만 다른 프로바이더 설정 형식으로 변환. 백업 필수, 토큰 값은 저장소 밖.
- 토큰: Codex·OpenCode에서 MCP 도구 정의가 통째로 실리는지 P0에서 재고, 그렇다면 세션별로 필요한 서버만 붙이는 방법을 검토.

### 3.6 여러 PC에서 쓰기

- 개인 스킬(Hermes가 만든 12개, Codex의 한국어 스킬 2개 등)은 사용자 계정의 새 비공개 저장소 `<login>/paseo_skills` 한 곳에 모아요. `paseo_share`와 섞지 않아요. `ps-share`의 저장소 준비 절차(비공개 확인, 관계없는 같은 이름 저장소 거부)를 그대로 써요.
- 원본이 있는 PC가 올리고, 다른 PC는 `~/.paseobility/catalog/vault/`로 받아 읽기만 해요. 한 방향이라 충돌이 없어요.
- 올리기 전에 비밀값 패턴을 검사하고, 걸리면 그 스킬은 올리지 않아요.
- 묶음 스킬과 외부에서 받은 스킬은 옮기지 않아요. PC마다 자기 폴더를 색인해요.
- Paseobility 저장소는 스킬 원본일 뿐이라 개인 스킬의 목적지로 쓰지 않아요.

### 3.7 스킬끼리 부딪힐 때

2026-11-10 실측: 이름 115개 중 51개가 두 곳 이상에 있어요. 49개는 내용이 같고 2개가 달라요.

| 종류 | 실제 예 | 처리 |
|---|---|---|
| 같은 이름, 같은 내용 | 49개 (Cloudflare 계열 등) | 목록에 한 줄만. 문제없음 |
| 같은 이름, 다른 판 | `paseo-multi` (Codex 쪽이 옛 판) | 출처 우선순위로 하나만 고르고, `conflicts`가 어긋난 사본을 알려요 |
| 같은 이름, 다른 스킬 | `pdf` (Codex 것과 Hermes 것) | 목록에 `pdf (codex)`, `pdf (hermes)`로 나눠 적어요 |
| 하는 일이 겹침 | 브라우저 4개, 디자인 3개, 한국어 문체 2개 | 묶음마다 "언제 어느 것"을 한 줄씩 적어 두고 목록에 같이 보여줘요 |
| 지침이 서로 반대 | 브라우저 스킬마다 기본 브라우저가 다름 | 한 작업에 주 스킬은 하나. 아래 우선순위를 따라요 |
| 옛 이름과 새 이름이 같이 설치됨 | `paseo-god` 옆에 `ps-god` | 설치 스크립트가 경고하고, `--migrate-skills`로 옛 것을 백업으로 옮겨요 |

**우선순위** (위가 이겨요)
1. 사용자가 이번 대화에서 한 말.
2. 프로젝트 지침(`AGENTS.md`, `CLAUDE.md`).
3. 하네스(`ps-god`, `ps-plan` 등): 일하는 순서와 검증 방법을 정해요.
4. 목록에서 가져온 전문 스킬: 그 분야의 사실과 절차만 보태요. 하네스의 검증을 건너뛰게 하지 못해요.

- 출처 우선순위 기본값은 Paseobility → 개인 스킬 보관소 → Hermes → Claude → Codex예요. 사용자 폴더의 설정으로 바꿀 수 있어요.
- 한 번에 가져오는 전문 스킬은 하나예요. 둘이 필요하면 에이전트가 이유를 한 줄로 밝히고 두 번째를 읽어요.
- 겹침 묶음과 "언제 어느 것" 문장은 처음 한 번 에이전트가 초안을 만들고 사용자가 확인해요. 사용자 폴더에 둬요.
