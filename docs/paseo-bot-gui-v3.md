# Paseo bot v3 routing and composer

The command/inspect surface keeps the chat primary and the board secondary. The composer groups project, model and effort choices with the input; each defaults to automatic. Plan cards show the server-resolved work model and the reason. Existing Paseo theme colors supply surfaces, borders and status colors in both themes. On compact screens controls wrap and the board replaces the chat until closed.

The GUI sends only aliases. The service checks the active registry and a fixed model/effort allowlist, applies the selection to every plan step, and includes it in the plan digest. It never accepts cwd or commands from the GUI. The manager's task text and classifications remain untrusted. Normal work defaults to Codex GPT-6.1 Terra high; only the hardest design/debug work selects Claude, and lightweight work uses OpenCode Go. A failed Terra model availability check falls back to Sol; confirmed GPT quota errors fall back to Claude, then OpenCode Go on a confirmed Claude quota error. Other failures, permissions, missing acknowledgements, and ambiguous outcomes stop without replay. Each retry uses the completed attempt's workspace ID and checks the returned path; already tried models are not repeated. The bridge returns a fixed error category, never raw provider errors.

The profiles provide host permission modes, while model IDs and provider families are constrained in the bridge; CommandCode is not selectable. Neither a rendered fixture nor a passed unit test proves live provider limits, desktop integration or deployment.
